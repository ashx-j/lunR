# lunR

Custom CLI coding agent derived from pi: own TUI, features, architecture. Built-in theme: `moon` (grayscale white-on-black + vibrant syntax/accent). Roadmap: 1. Custom TUI ✓ 2. Custom features ✓ 3. Cron ✓ 4. Gateway ✓ (Discord/Telegram).

## Project Layout

lunR IS the root git repo. Reference repos (`pi/`, `hermes-agent/`, `kimi-cli/`, `extension-repos/`) are gitignored study material — never import from them unless explicitly decided.

```
packages/tui/ terminal UI · packages/ai/ provider integrations · packages/agent/ core logic
packages/coding-agent/ CLI entry (bin: lunr → dist/cli.js) · packages/orchestrator/ orchestration
```

## Toolchain

TypeScript (ESM). Build with `tsgo`, order tui → ai → agent → coding-agent → orchestrator. Lint: `biome check packages/` (excludes `builtin-extensions/` + `*.generated.ts`). Tests: `vitest --run` (coding-agent), `node --test` (tui). Themes: JSON in `coding-agent/src/modes/interactive/theme/`.

## Agent Rules

Read before editing; ask when ambiguous; touch only what the task requires; small scoped commits with why-messages. Don't rewrite working code or add deps without checking existing ones. Never commit secrets/.env; never force-push shared branches; confirm destructive commands. Git: branch + PR before merging. Public docs must not contain local setup/env/secrets. **This file is the single source of truth — after work, update Current State + build/test block, log decisions (+ one-line why) under Decisions, gotchas under Notes. Append dated entries; delete stale/superseded ones.**

# Architecture (permanent)

- **Features = baked-in extensions + bridges.** `packages/coding-agent/src/builtin-extensions/` (inline factories via main.ts; hidden from UI; upstream files carry `// @ts-nocheck`; biome-excluded; assets ride `copy-assets`). Roster: simple-pi-memory, pi-tps, ashxj-tui, pi-ollama-cloud, ashxj-spinners, ashxj-thinking, pi-intercom, pi-prompt-template-model, pi-subagents, pi-web-access, pi-lsp-extension, pi-mcp-adapter, lunr-local-providers, lunr-behavior, lunr-cron, lunr-skill-creator (last four lunR-native). Removed: context-mode (trailing user-message injection hijacked the model), MattDevy + narumiruna collections.
- **Bridges** via `globalThis[Symbol.for("@lunr/...")]` (avoids cycles into vendored code); direction follows state ownership.
- **Barrel-import guard:** never runtime-barrel-import `@earendil-works/pi-coding-agent` under `builtin-extensions/` — import concrete modules (~89 vitest load-failures once; agent-bridge lazy-imports the session factory for the same reason). `complete`/`streamSimple`/`getModel` from `@earendil-works/pi-ai/compat`, NOT package index.
- **Cron:** shared `core/cron` fires in BOTH TUI (`sendUserMessage` into live session) and gateway daemon (fresh headless session per fire — output files are the audit trail). Single `jobs.json` at `~/.lunr/agent/cron/`, single-process-per-store. Turns wrap `prompt()` in `runWithOrigin` (ALS) so the `cron` tool stamps `origin` + defaults `deliver:"origin"`. Gateway fires fall back through settings.json `cronFallbackModels` (hand-edited "provider/modelId" list) on timeout/any error — per-attempt budget = jobTimeoutMs/candidates, success prefixes `[fell back to ...]`; TUI fires keep the live model.
- **Gateway:** `src/gateway/` — Telegram (zero-dep `getUpdates` long-poll) + Discord (discord.js, mention-gated, autoThread; NO GuildMembers intent — privileged-intent trap keeps the bot offline). Authz fail-closed; adapters drop ALL bot-authored messages. New platforms via `ADAPTER_FACTORIES`, must set `metadata.mentionedBot`. Platform specifics (typing, debounce, Markdown fallback) live INSIDE adapters.
- **Footer owned by ashxj-tui** (`ctx.ui.setFooter`); segment toggles (`footerMcp`/`footerLsp`/`footerContext`/`footerTokens`/`footerStatuses`) are render-time bridge reads via `CustomizeBridge`; any other `setFooter` clobbers it.
- **Permission modes** per-session (`/mode` `/manual` `/yolo` `/plan` `/auto`, Shift+Tab cycles `manual → yolo → plan → auto`), default via `defaultPermissionMode` (manual); auto force-enables rollback; plan hard-blocks mutating tools via `gateToolCall` + `PLAN_MODE_ADDENDUM`. Fail-closed without an approval handler; mutating tools gated by capability metadata, not name allowlist. Auto-activated swarms (>2 parallel subagents in one call) gated in manual AND yolo; explicit /swarm turns pre-approved.
- **Rollback** (`core/rollback.ts`): pre-edit snapshots per user-turn; persistent rewind via `fork` (survives `-c`); `/undo` forks too but restores NO files; tree baseline at turn START; `shadow-git` falls back to `copies`.

# Notes / gotchas

- **Theme canonical file:** `moon.json` is the loaded builtin; `default.json` is UNTRACKED + unwired. Optional tokens `accent2` (#689BFF, `?? accent`) + `white` (#e8e8e8, `?? text`), mirror `thinkingMax`. Non-color `glyphs` section: `promptMoon` (☾) + `promptArrow` (>) — editor prompt glyph, read by ashxj-tui at render; empty string hides that part; the `promptSymbol` /settings toggle is the master on/off. User themes still work.
- **Selector components must use the keybinding layer** (`getKeybindings().matches(data, "tui.select.cancel")`) — raw `\x1b` byte checks never fire under the Kitty keyboard protocol (Esc arrives as CSI-u). This was the `/processes` stuck-modal bug.
- **Ctrl+V never reaches the app on Windows** — VS Code/Windows Terminal own it as their text paste; an image-only clipboard pastes nothing. `Alt+V` is the win32 `app.clipboard.pasteImage` default (matched as legacy `\x1bv` without Kitty, CSI-u `\x1b[118;3u` with it; both fine in VS Code's terminal with default settings). Don't try to "fix" Ctrl+V.
- **Process registry** tracks directly-spawned shell pids only; `nohup ... &` grandchildren untracked. Exited processes linger with exit code (3s noise gate, 5min TTL); quit prompt ignores exited entries.
- vite/oxc rejects `import type { A, type B }` — use `import type { A, B }`; tsgo accepts both.
- Telegram length limit is UTF-16 units = JS `string.length`. Busy-session slash commands (`/stop` `/new`) must bypass the session guard or they deadlock the running turn. Discord thread `editMessage` needs the adapter's messageId→channel map.
- `// lunr:` markers in code flag upstream edits for future syncs. Most-edited sync surfaces: `ashxj-tui.ts`, `interactive-mode.ts`, `agent-session.ts`, `bash.ts`, `settings-manager.ts`, `main.ts`, `builtin-extensions/*`.
- Old settings keys from removed features are left in user settings.json (harmless, shallow-merged).
- **Injected-prompt collapse** (`core/injected-prompt.ts`) is render-time only, keyed on the literal `[SWARM MODE]` / `[DEEP RESEARCH]` prefixes and the goal `<!-- pi-goal-prompt: -->` marker; the model still receives the full prompt; goal summary extracted from `<goal_objective>`.
- **Gateway inbound images (v1):** `MessageEvent.attachments` (base64) → `processImage` → `ImageContent`. Telegram's poll loop AWAITS `dispatchUpdate`, so a large media download blocks the next `getUpdates` (acceptable v1; capped 10MB pre-download). Non-images dropped; captions pass as text; gated chats still waste the download.
- **Goal auto-resume** fires on `before_agent_start` when `usage_limited` and EITHER `resumeAfter` has elapsed (rare — needs a parseable reset time in the provider error) OR a cron-fired turn arrives (`isCronFire()` — the cron IS the timing mechanism). Manual turns never hijack; `/goal resume` stays the manual path. Gateway cron fires are headless and CANNOT see a TUI session's goal state.
- **`/plan <task>`** switches to the plan permission mode AND sends the trailing text. While already in plan it restores the previous mode (or yolo if none) and sends — the “looks good, implement it” path. Bare `/plan` still toggles; `/plan off` restores.
- **skill-creator skill** ships via the lunr-skill-creator extension's `resources_discover` hook (SKILL.md rides copy-assets); `disable-model-invocation: true` = explicit `/skill:skill-creator` only.
- **`npx lunr --print` responds but does not exit on its own in this environment** (2026-08-03; reproduces with `--no-extensions` — builtin extensions/core still load, likely intercom broker or a core handle). Use `timeout <s> npx lunr --print ...` in scripts until investigated.

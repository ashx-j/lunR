### Findings

- **High, lifecycle:** `pi-lsp-extension/src/index.ts:143-156,616-622` installs a process-wide `uncaughtException` listener on each factory creation and never removes it. With no prior listeners, its non-EPIPE branch logs instead of terminating the process. Reloads can accumulate listeners and replay earlier listener snapshots.
- **Medium, duplicate command:** `pi-prompt-template-model/index.ts:1778` and `pi-subagents/src/slash/prompt-workflows.ts:298` both register `/chain-prompts`. `core/extensions/runner.ts:579-608` disambiguates collisions as `chain-prompts:1` and `chain-prompts:2`, so the advertised plain command does not resolve to either implementation.
- **Medium, external identity:** `pi-mcp-adapter/mcp-oauth-provider.ts:119-135` defaults OAuth registration to `"Pi Coding Agent"` and the upstream adapter URL. `server-manager.ts:243,340` and `host-html-template.ts:169` also identify the MCP client or host as pi. These are externally visible, unlike internal compatibility symbols.
- **Low, agent-facing and UI copy:** The MCP tool description says “Non-MCP Pi tools” (`pi-mcp-adapter/direct-tools.ts:146`); intercom describes “another pi session” (`pi-intercom/index.ts:1444-1458`). MCP setup repeatedly calls the actual lunR agent directory “Pi” (`pi-mcp-adapter/mcp-setup-panel.ts:437-491`). The watchdog prompt also identifies its session as Pi (`pi-subagents/src/watchdog/review.ts:208`).
- **Low, shipped guidance:** `docs/security.md:35-47` instructs users to run “pi”; `docs/packages.md:133` promotes the pi.dev gallery. Multiple shipped examples direct users to `~/.pi/agent` or `pi -e`, including `examples/sdk/06-extensions.ts:8-9` and `examples/extensions/claude-rules.ts:15`. Those paths contradict lunR’s documented `~/.lunr/agent` setup.
- **Low, dormant source guidance:** `pi-ollama-cloud/index.ts:8` and `pi-lsp-extension/bemol-extension/index.ts:8` retain `~/.pi` installation instructions. The latter is not registered as a built-in.

**Intentional or unresolved remnants.** The workspace package names, extension factory argument `pi`, package metadata key `"pi"`, and `PI_*` environment contracts are documented compatibility names, not evidence of wrong-path writes. Active extension path resolvers default to `.lunr`; `pi-mcp-adapter/config.ts:113-119,198-259` deliberately reads project `.pi/mcp.json` only when `.lunr/mcp.json` is absent, while writing the lunR path. `migrations.ts:332-401` deliberately *copies* selected old `~/.pi` state. The sole confirmed `pi.dev` runtime default is the `/share` **viewer URL**, `config.ts:172-177`, disclosed in `docs/usage.md:173`; it is not a catalog or installer request. `pi-web-access/openai-search.ts:349` sends `originator: "pi"` on the Codex route. Its protocol requirement was not verified, so changing that header without qualification would be unsafe. Browser and web-access tools overlap in page retrieval but have distinct browser-interaction and search roles.

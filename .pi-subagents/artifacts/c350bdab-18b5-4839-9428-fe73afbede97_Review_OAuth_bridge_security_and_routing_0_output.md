I found two security blockers and three behavior or lifecycle defects in the current working-tree diff. I made no edits.

- **High, legacy OAuth leak:** `packages/ai/src/api/anthropic-messages.ts:510` rejects OAuth-shaped `apiKey` values but does not inspect authentication headers. The same file accepts header-owned authentication at `:279-287` and forwards those headers at `:878-895`. A bearer or `x-api-key` header containing a legacy OAuth token can therefore reach direct Anthropic HTTP. Reject OAuth-shaped credentials in effective auth headers before constructing the client.
- **High, stale signed replay:** `packages/ai/src/api/anthropic-claude-code-bridge.ts:49-58` matches a replay carrier using only assistant text and tool calls. Editing or removing thinking leaves that match intact, so the old signed native assistant content can be replayed after an edit or compaction. The check also has no account identity. Bind carriers to the full canonical assistant content and connection fingerprint, or discard them when either cannot be verified.
- **Medium, API-key catalog regression:** `packages/ai/src/providers/anthropic.ts:28-30` filters models using the stored external connection even when an ambient genuine API key wins auth resolution. `packages/ai/src/models.ts:418` applies that filter to available models. Select the filter from effective auth, not merely the stored credential.
- **Medium, ignored reasoning controls:** `packages/ai/src/api/anthropic-claude-code-bridge.ts:186-189` forwards `reasoning` from simple-stream options but ignores the Anthropic `stream()` options `thinkingEnabled` and `effort`. In particular, `thinkingEnabled: false` does not request disabled thinking. Translate supported controls or reject them explicitly.
- **Medium, timeout breaks cancellation protocol:** `packages/ai/src/api/anthropic-claude-code-bridge.ts:195-200` force-terminates the worker and native PID on the idle timer without first sending `cancel`. The timer resets on text or thinking deltas, but not replay acknowledgments, which the worker does not forward. Send `cancel` first and expose bounded replay progress to the adapter before using targeted force-kill.

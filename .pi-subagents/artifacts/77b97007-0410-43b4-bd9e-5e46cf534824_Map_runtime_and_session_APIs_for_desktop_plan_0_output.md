## Architecture recommendation

Build the Windows Electron app around an **app-owned lunR runtime process**, separate from the React renderer. The Electron main process should manage that process and a typed local connection; React should receive structured events and send commands, never own an `AgentSession` or parse terminal output. A renderer reload or closed window must not dispose an active run. This local boundary can later support an authenticated remote transport, but remote implementation remains paused under `REMOTE_DESKTOP_HANDOFF.md`.

Install a **version-matched `@ashx-j/lunr` dependency inside the app**. Do not launch, update, or replace the user's global `lunr`. Reuse `createAgentSessionServices`, `createAgentSessionFromServices`, and `AgentSessionRuntime` for cwd-bound services and session replacement (`packages/coding-agent/src/core/agent-session-services.ts:137,194`; `agent-session-runtime.ts:77,193`). Reuse `AgentSession.prompt`, `steer`, `followUp`, `subscribe`, and `abort` for execution (`agent-session.ts:893,1274,1495,1515,1702`). Steering is **queued after the current assistant turn's tool calls**, not an immediate interruption (`docs/sdk.md`, Prompting and Message Queueing).

Keep `SessionManager` JSONL as conversation history shared with the TUI. Store desktop-only layout, drafts, and window state separately, keyed to session identity; do not make a second chat-history database. `SessionManager.list/listAll`, `open`, `getEntries`, `getTree`, and `buildSessionContext` provide the base (`session-manager.ts:1189–1239,1441–1566`). Build a native graphical interface for **all builtin features**, including approvals, settings, tools, subagents, and session navigation. Third-party custom terminal UI is outside this graphical contract; identify it as terminal-only rather than pretending the current RPC UI methods reproduce it.

## Missing contracts and findings

- **Blocker: desktop approval adapter.** `AgentSession` calls `gateToolCall` before execution (`core/agent-session.ts:494`). Manual mode blocks mutations without an approval handler (`core/permissions.ts:437–505`). The TUI installs one (`modes/interactive/interactive-mode.ts:922`), but RPC's UI dialogs do not install that permission handler (`modes/rpc/rpc-mode.ts:318–348`). The desktop host needs an owned, correlated approval channel with disconnect and timeout policy, plus explicit mode lifecycle.
- **Blocker: project trust parity.** CLI startup resolves trust before loading cwd-bound settings and resources (`main.ts:761–820`). Direct `SettingsManager.create` defaults `projectTrusted` to true (`core/settings-manager.ts:370–404`); a bare SDK host must not silently load executable project extensions. Reuse the CLI trust decision flow when building desktop services.
- **High: one controller per session.** `SessionManager` appends to JSONL without a session-owner lock (`core/session-manager.ts:946–981`). Settings and auth have their own file locks, but these do not prevent a TUI and desktop process from controlling the same conversation. Add an exclusive session control lease and refuse a second writer; permit read-only viewing or an explicit handoff.
- **High: reconnect needs an atomic snapshot boundary.** RPC offers `get_state`, `get_messages`, `get_entries(since)`, `get_tree`, and live events (`modes/rpc/rpc-types.ts:16–70,93–181`), but no ordered snapshot-plus-event cursor for active tool output, queued work, or pending approvals. `get_entries` cursors cover completed JSONL entries only (`rpc-mode.ts:612–629`). Define versioned typed commands/events, session generation, sequence numbers, snapshot, replay, and stale-command rejection in the host.
- **High: branch position cannot be inferred solely from the last JSONL entry.** `SessionManager.branch` changes its in-memory leaf, while reopening indexes the last appended entry as leaf (`core/session-manager.ts:889–907,1289–1298`). The live host should supply the authoritative leaf in snapshots; test restart behavior before promising exact branch restoration.
- **High: RPC is a reference, not the desktop host unchanged.** Its stdin EOF calls shutdown and disposes the runtime (`modes/rpc/rpc-mode.ts:697–717,778–781`). Several TUI UI methods are no-ops or degraded in RPC (`docs/rpc.md`, Extension UI Protocol), and builtin TUI commands such as `/settings` are absent (`docs/rpc.md`, `get_commands`). Create graphical adapters over the shared runtime rather than treating a subprocess RPC connection as detachable ownership.
- **Medium: builtin loading is a host responsibility.** The SDK's default loader discovers resources but does not itself assemble the CLI builtin roster (`core/sdk.ts:164–179`; `builtin-extensions/index.ts:33–79`; `main.ts:744`). Specify how desktop loads the complete roster while replacing TUI-specific presentation. `ExtensionMode` currently has only `tui | rpc | json | print` (`core/extensions/types.ts:301`).
- **Medium: shared settings require durability and diagnostics.** Use the existing agent directory, credentials, project settings, and session-dir precedence rather than app copies (`docs/sdk.md`, Directories; `docs/settings.md`). `SettingsManager` queues writes; the host must `flush()` and report `drainErrors()` (`core/settings-manager.ts:617–715`). Respect session retention before attaching to historical sessions (`main.ts:708–725`).

Focused acceptance tests should cover a renderer reload during a long tool call and pending approval; reconnect with exactly one ordered snapshot and no duplicated events; stale controller rejection after handoff; simultaneous TUI/desktop open of one JSONL; untrusted project resources staying unloaded; manual-mode approval, rejection, and disconnect; TUI-created history appearing in desktop and vice versa; and an app-bundled runtime running without touching the installed global CLI. No live credentials or personal sessions are needed for these tests.

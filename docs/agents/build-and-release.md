# Build, test and release

Read before building, testing, packaging or publishing lunR.

## Build

- Offline build order: tsgo for tui, ai and agent (`npx tsgo -p <pkg>/tsconfig.build.json`), then `npm --prefix packages/coding-agent run build` (tsgo, assets and the Node bundle; bare tsgo leaves `dist/node-runtime` stale), then orchestrator. Root `npm run build` runs this offline sequence. CI does too and asserts `packages/ai` stays clean; live catalog generation is never part of PR validation.
- **Never `npm run build` in `packages/ai`** (generate-models catalog drift).
- JSON catalog: `npm run sync:model-catalog` (needs network). Do not hook generate into root `npm run build`.
- Package builds are the production typecheck; the root check does not typecheck test fixtures. Coding-agent external dependencies are exact, and the standalone installer lock preserves workspace-local resolutions such as Zod 4. The relative-import check skips vendored `builtin-extensions/` and gitignored study trees, and also fails coding-agent `core/` imports from `modes/` outside its named allowlist.
- Lint: `biome check packages/` (excludes `builtin-extensions/` and `*.generated.ts`).
- Pre-commit runs `scripts/check-lockfile-commit.mjs` then `npm run check` (Biome `--write` plus `check:repo`: pinned deps, relative imports and core-to-modes imports, `@ts-nocheck` count, shrinkwrap, installer lock, publish-workflow policy, browser smoke), so it needs installed dependencies. CI runs `check:ci`, the same without `--write`, so unformatted code fails.
- `@ts-nocheck` count: `docs/agents/architecture.md` (the Features line) keeps the number and its breakdown. `npm run check:ts-nocheck` fails if the count rises; lower its constant when the count drops.

## Test

- Packages: `vitest --run` (ai, agent, coding-agent), `node --test` (tui).
- `bash test.sh --workspace=packages/coding-agent -- <test files> --maxWorkers=1` runs with disposable home/profile/cache/temp directories and an allowlisted environment without credentials. Plain package `vitest --run` uses the caller's profile.
- First paint and first request: after the builds, `node scripts/check-interactive-first-paint.mjs [cli]` checks stalled and failed hydration plus first-turn subagent/MCP/LSP/fetch, and compares the full default tool payload with browser-on and browser-off baseline hashes. A second pair of runs gives the faux model native tool loading and pins the loaded list, the deferred list and the `load_tools` hash.
- Async child questions: `node scripts/check-subagent-questions.mjs` (also `--idle`), logs under `.artifacts/`.
- `ci.yml` runs on pushes and pull requests for `master` and `dev/tui`, on Linux, macOS and Windows. Before 2026-11-26 it ran for `master` only, so the macOS and Windows jobs had never run on the dev branch's changes.
- CI's Script tests step installs bun 1.3.14, the version `build-binaries.yml` pins, because `scripts/build-standalone.test.mjs` bundles its probe with bun.
- Fixture gotchas live in [testing.md](testing.md).

## Run

- From this repo, `npx lunr` runs the workspace bin (`packages/coding-agent/dist/cli.js`), not the installed `@ashx-j/lunr`; rebuild first. Worktrees can share one npm bin shim, so verify a worktree with `node packages/coding-agent/dist/cli.js`. Local npx is not a published smoke test.
- `lunr update` is npm global `@ashx-j/lunr` only. Workspace `PACKAGE_NAME !== NPM_CLI_PACKAGE` skips the nag and refuses to self-update.

## Release and install

- Install: `npm i -g @ashx-j/lunr` (Node >= 22.19).
- On Windows, `node scripts/release.mjs publish-tag` fails: `run()` spawns with `shell: true` there, so the `-m "Release vX"` tag message splits into words. 0.2.33 and 0.2.34 were tagged by hand. Tag from Linux or macOS.
- Qualify a stable release with real turns before tagging: merge the release PR, build that master commit with a clean tree, then `npm run qualify -- --profile <agent dir signed in with /login anthropic>`. `scripts/qualify-release.mjs` runs 8 Sonnet 5.5 requests (at most 12) on a private temporary copy of only the Anthropic login with fixed settings: history cache reads must grow and writes stay under 300 tokens per request, one env-prefixed command in auto mode must be reviewed and allowed, a 1 s-late producer on an open stdin pipe must reach the model and `-p` must still exit, `-p` with no prompt must exit non-zero, and the first request must fit `FIRST_REQUEST_TOKEN_BUDGET`. Raise that budget in the PR that adds a tool or prompt text, not at release time. Exit 3 means no subscription login, 4 a pass that was not recorded. It also prints the newest run of each publish workflow without failing on it.
- A pass is the commit status `lunr/qualify-release` on HEAD with the sha256 of the built CLI entry and its bundled runtime. The script refuses to record when tracked files or `packages/`/`scripts/` have uncommitted changes, or a tracked source is newer than `dist/`. The status is a reminder that the check ran on that commit, not proof: anyone with write access can set it.
- The gate is off by default. `publish.mjs` checks the status only with `--require-qualify`, and `publish-npm.yml` passes it when the repository variable `LUNR_REQUIRE_QUALIFY` is `true` (`gh variable set LUNR_REQUIRE_QUALIFY --body true`) or a manual run ticks `require_qualify`. `skip_qualify` on a manual run turns it off once and logs a warning. The dev channel and `release:local` never check it and never call `gh` for it.
- Release prep checks formatting without writing; normalize inherited formatting on the release branch first. Bump with `npm run version:patch`.
- Workspace names stay `@earendil-works/pi-*`. `scripts/publish.mjs` rewrites **package.json and compiled JS/d.ts imports** to `@ashx-j/lunr{,-ai,-tui,-agent}`. Rewriting names only is not enough; `0.1.0` crashed with `Cannot find package '@earendil-works/pi-ai'`. Never publish `@earendil-works/*`.
- CI: `.github/workflows/publish-npm.yml` on `v*` tags with `secrets.NPM_TOKEN`. It builds, runs `check:ci` and the tests before publishing, then `scripts/verify-npm-release.mjs` checks every registry tarball against the integrity `publish.mjs --manifest` recorded and does a fresh isolated install. Trusted publishing needs npm-side setup by the owner first.
- A release publishes seven packages: the four public packages plus three native CuaDriver payloads. The CLI does not depend on the payloads (a dependency's shrinkwrap would install all three on every platform); `core/computer-use/runtime.ts` downloads the host's payload tarball at the CLI version on first use, from the npm-configured registry, outside the workflow's 90 s call bound, resumable through a `.part` file and an HTTP range request, and checks its archive against the pinned SHA-256. The standalone installer lock still lists them, because a root `npm ci` does check `os`/`cpu`. `npm run publish:dry` packs all seven; `scripts/publish.mjs` accepts both npm 10 array and npm 12 keyed `npm pack --json` output.
- npm accepts a publish minutes before the CLI metadata and tarball resolve. Treat a tag as shipped only after every registry tarball matches its integrity and a fresh isolated install reports the new version.
- Published npm docs are `packages/coding-agent/{README.md,docs/**,examples/**,CHANGELOG.md}` (packed via `package.json` `files`). Repo-root README, root `docs/` and untracked `lunr-docs/` are not what npmjs shows. `npm pack --dry-run --ignore-scripts --json --workspace=@earendil-works/pi-coding-agent` lists them. Author shipped docs for `@ashx-j/lunr` / `lunr` / `~/.lunr/`; keep ExtensionAPI `pi`, package.json `"pi"` and `PI_*` names.
- `THIRD_PARTY_NOTICES` must stay in the public files allowlist; staging copies both notices. Notice tests compare complete source bytes, not author names.
- Node bundle: CLI and SDK exports must share chunks for class identity; preserve original module URLs and external native packages. pi-ai, pi-agent-core and pi-tui stay external to it and ship their own `dist/bundle/` build (interactive-startup.md); `packages/coding-agent`'s `build` script makes those bundles first, so a build path that skips it leaves them stale. Public `./rpc-entry` resolves through `dist/rpc.js`, which prefers the bundled runtime. Publish checks verify every exported target and scan staged `dist` after specifier rewriting.
- Tree-sitter grammars ship as copied files, not as the `tree-sitter-wasms` dependency: `copy-assets` runs `scripts/copy-tree-sitter-grammars.mjs`, which copies every `tree-sitter-*.wasm` name found in `parser-manager.ts`. A new language needs only its map entry there. Standalone binaries cannot resolve them through `import.meta.url` (it points into `$bunfs`), so `copy-binary-assets` and `build-binaries.sh` also put `grammars/` and web-tree-sitter's `tree-sitter.wasm` beside the executable, where `parser-manager.ts` finds them through `getPackageDir()`. They come from the same copy script as `dist`, so the vendored builds win there too; a missing file is reported once ("tree-sitter grammar files are missing: lunR expected them in …") and not retried. Bun leaves `exitCode` null for a command it could not spawn (node sets -2), so code that decides whether a child is running must check `pid`; `LspClient.shutdown` did not, and each `lsp_diagnostics` call in the binary waited 3 s.
- Package size: maps, `exy.png` and catalog extras are cut. The tarball is 7.27 MB packed on `dev/tui` (2026-11-26), up from 5.41 MB because the 18 tree-sitter grammars (23.9 MB unpacked) now ship inside it instead of the whole `tree-sitter-wasms` dependency. npm does not check `os`/`cpu` for packages it fills from a dependency's `npm-shrinkwrap.json`, so any optional platform package in the shrinkwrap installs on every platform (the CuaDriver payloads are no longer listed for this reason). A file or URL tarball install ignores the shrinkwrap, and so does a test registry that omits `_hasShrinkwrap: true` from the version manifest; `scripts/check-computer-use-install.mjs` sets it. See `docs/package-size-report.md`.

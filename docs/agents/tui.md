# Interactive TUI

Read before changing startup, rendering, input, slash commands, `/settings` or onboarding.

## Startup

- First paint: keep the startup view's imports free of model/auth/resource services. The shared moon editor must retain its identity; forwarding callbacks to itself recurses. Snapshot its display values before session invalidation so `/new` and `/resume` cannot render a disposed context. First-frame timing waits for a completed synchronized-output content frame and uses time since process start. Read `docs/agents/interactive-startup.md` before startup, packaging or measurement changes.
- Cold start: interactive loads `lightBuiltinExtensions` only; deferred builtins attach after `ui.start()`, and `init()`/`getUserInput()` do not wait. Every `session.prompt`/`sendUserMessage` and `/new` waits for attach. `ModelRuntime.create()` and TUI init are cache-only (no GitHub/provider lists; local Ollama/LM Studio probes skip on `allowNetwork: false`). Initial interactive `resourceLoader.reload` skips missing npm/git auto-install. `PI_TIMING=1` prints timings after `init()` (time-to-type).
- Once the first-paint TUI owns the screen, any stdout/stderr write (runtime creation in `main.ts`, or later) moves the cursor outside TUI bookkeeping and leaves stale rows such as a second boot header. Route startup output through runtime diagnostics or managed components after history restoration. Do not fix it with repeated full-screen clears.
- Tab title: `process.title` + OSC 0 `lunr` in `cli-runtime.ts` before importing main; InteractiveMode then sets `lunr - [session -] cwd`. Do not call `ctx.ui.setTitle` from ashxj-spinners. It also pushes the xterm title stack (`CSI 22;0 t`) with the first title and pops it (`CSI 23;0 t`) as the last write in the exit handler, so the tab gets its old title back; nothing may write a title after the pop.
- Onboarding (`components/onboarding.ts`) shows when `modelRuntime.listCredentials()` (the list `lunr doctor` reports as Logins) is empty and the session has no model, on every interactive launch; no seen flag. An environment key or local provider with a model skips it. It waits for deferred builtins, never runs from the startup view, and leaves a selector the user already opened alone. Rows name only the `FEATURED_PROVIDER_IDS` providers from `getLoginProviderOptions`, then "and more" without a count, so each fits one line; `LOCAL_SERVERS` ids are left out. After any login, including the custom endpoint wizard (through `LoginFlowHost`), `openModelSelectorIfUnset` opens /model when the session still has no model.
- **Stop proposing boot-screen art.** Slim box only; ask first.

## Look

- Theme: `moon.json` is the builtin; `default.json` is untracked and unwired. Themes are JSON in `coding-agent/src/modes/interactive/theme/`. The chatbox uses `promptArrow`; legacy `promptMoon` is accepted but ignored. Body lines keep `│` side rails with the rounded top/bottom rules and thinking chip. Do not clobber `ChatboxEditor.borderColor`.
- Chatbox thinking chip prints the effective level including `xhigh`/`max`; `/thinking` and its completions offer only `getSupportedThinkingLevels`; `/thinking <level>` is the only level command. Ctrl+T cycles levels; `/thinking hide` hides blocks. Model and level changes print no status.
- Live thinking uses `reasoningDisplay`: auto is one line for `openai-codex`, four lines otherwise. One-line mode leaves its bottom unpadded because the working Loader already prepends a blank row; four-line tails do not pad. Both use the revealed prefix when smoothing; collapse needs provider completion and full reveal. Collapsed Codex snippets strip `**` at display only.
- Smooth streaming is interactive-TUI only (`smooth-streaming.ts` + timer in `interactive-mode.ts`). Segment state lives on content-block objects, not the shallow-copied AssistantMessage, because providers append into the same block instances.
- Collapsed same-name tool rows are header-only and tree their details through `GroupedCallText`; wrap details after reserving the five-column gutter. Collapsed failures keep the tree and red state but defer bodies to expansion. Subagent compact widgets are the exception. `app.tools.expand` has no default key; `/tree` uses `ctrl+o`.
- Browser activity is presentation-only: backend call IDs, results, permissions and history stay unchanged. One live card follows browser calls until `agent_end`.
- Copyable `lunr-copy` text is parsed before the assistant-body trim. The payload is source text between the fences; never derive clipboard text from rendered lines. The box is clickable only after the closing fence is revealed. Keep `Component.handleClick` X optional.
- The wait card reads elapsed time from the leading `Waited`, `Wait timed out after` or `Wait aborted after` phrase; keep it in sync if those strings change.
- Extension widget layout sorts built-in keys explicitly. Keep `todos` directly before `subagent-async` with only the dim rule between.
- The subagent spinner setting changes the shared foreground/async glyph source live (default `braille`, choices from `unicode-animations`). Animation ticks stay unbounded and scale by each interval; a `% 10` counter freezes longer animations.
- Plan footer uses a 60s usage cache. Preferred window is `/settings` Plan usage window (`5h` | `weekly`); missing 5h falls back to weekly. In Customize, Plan usage hides the segment while Plan bar hides only the █░ fill. The TPS counter is its own toggle; feature statuses only gate plan/goal.
- Injected-prompt collapse is render-only (`[DEEP RESEARCH]` / goal marker).

## Input, mouse and scrolling

- Sticky chat + alt-screen has no native scrollback. While pinned, SGR 1000+1006 mouse tracking is on: wheel scrolls (Ctrl+wheel pages), left-drag does nothing, click expands/collapses a thinking run or tool card, Shift+drag is native selection, the last-column scrollbar drags. Do not use DECSET 1007 (collides with editor history).
- Pinned chat scroll reuses the last chat layout; do not re-layout or sync-render in `setChatScroll`. The overflow gutter is sticky. A scrolled-up view anchors matching rendered line sequences and falls back to the previous line position after width reflow. `findChatAnchor` searches copies nearest-first and stops at the first full-length match; keep its tie order (equal distance, earlier copy wins), which `test/chat-anchor.test.ts` checks against the old implementation.
- Selectors use the keybinding layer (`tui.select.cancel`), never raw `\x1b` (Kitty CSI-u).
- TUI input listeners never see Kitty key releases unless registered with `{ wantsKeyRelease: true }`. A partial escape sequence waits 40 ms; a lone ESC still flushes at 10 ms. `TUI.stop()` is idempotent.
- `app.exit` (Ctrl+D) runs through `ExitConfirmation` (`modes/interactive/exit-confirmation.ts`) in both the startup view and `InteractiveMode`, which share one instance across hydration; keep both handlers using it. If startup fails before `InteractiveMode` wires its key handlers, the startup view leaves the error text in place and shows no hint; later failures go through `handleCtrlD` like any other press.
- Win32: Ctrl+V is the terminal's; image paste is `Alt+V`. lunR cannot see keys the host never sends, so VS Code must forward it with `sendSequence` `\u001b[118;3u` (leaked `ESC v` also works) or use `/paste-image`. Paste inserts `[image_n]` chips, not a temp path; do not expand them back to paths on submit. The first-paint editor releases its startup paste callback at activation.
- Terminal notifications enable DECSET 1004 only while `terminal.attentionNotification` is on; TUI consumes `ESC [ I`/`ESC [ O` always. pty harnesses must write such reports in one write, or lunR reads a lone Escape plus typed text.
- Skill tag is a mention (`$pdf-tools`; character `+`/`~`/`$`, default `$`). Do not expand it into a `<skill>` block; `/skill:name` force-loads. Open the picker only at a token start. With `~`, `~/` and `~\` stay paths.

## Slash commands

- Builtin slash commands live in `modes/interactive/slash-dispatch.ts`: `SLASH_COMMAND_HANDLERS` maps each name and alias to a handler that parses its own arguments from the trimmed text, reaching InteractiveMode through `createSlashCommandHost`. A name ends at any whitespace (so `/plan` + newline + task runs `/plan`), and a no-argument builtin given text goes back to the editor with a usage status. Extension command names in `agent-session.ts` split the same way. Alt+Enter runs builtins at once, even while streaming. `/reclaim` and `/handoff` stay inline because they run before the detached-session guard. A new builtin needs a table entry and a handler; `test/slash-dispatch.test.ts` fails otherwise.
- Provider errors go through `describeProviderError` (`core/provider-error-display.ts`) in TUI and print mode: JSON `message` plus status, and a `/login` line on 401/403. User aborts and cancels render dim, not red. Collapsed cards say "click to expand" while `app.tools.expand` is unbound; a component that overrides `Container.render` keeps its own `handleClick` (the TUI flattens containers that don't).
- Print-mode sessions carry `origin: "print"` in the header (`SessionManager.markPrintOrigin`, only for sessions not yet on disk) and `/resume` tags them `print`. Indic graphemes (U+0900 to U+0DFF) measure one cell per spacing code point, matching wcwidth terminals; kitty and Ghostty draw them narrower.
- Unknown slash check (`modes/interactive/slash-guidance.ts`) runs only in the interactive submit chain, after builtins dispatch, and at the top of Alt+Enter (`handleFollowUp`), where the draft stays in the editor. It recognizes commands from dispatch, not autocomplete: `INTERACTIVE_BUILTIN_COMMAND_NAMES` (the whole builtin table, hidden entries included), `extensionRunner.getCommand` and prompt templates, so hidden commands stay recognized. Only `^/[a-z][a-z0-9-]*$` first tokens count; paths, `/skill:x`, `/foo:2`, text with a leading space and an unknown name that exists at `/<name>` or under the session cwd (two `existsSync` calls) pass through. Suggestions skip hidden commands and rank Damerau-Levenshtein <= 2 matches first, then fill from the picker's `fuzzyFilter`. A typo that names a directory in the project (`/models` with a `models/` folder) counts as a path and goes to the model. The leading-space test reads the untrimmed text the TUI `Editor` passes as `onSubmit`'s second argument. Gateway, RPC, print and ACP never reach it.
- Hidden commands (`hidden` on `BuiltinSlashCommand` and `RegisteredCommand`) are filtered only from listings: TUI autocomplete, unknown-command suggestions, `pi.getCommands()` and RPC `get_commands` (so ACP `available_commands_update` too). Dispatch never filters: the TUI submit chain, `extensionRunner.getCommand` (prompt, RPC, ACP, gateway) and `INTERACTIVE_BUILTIN_COMMAND_NAMES` keep hidden names. Gateway bot menus are a separate static list. Hidden builtins still shadow same-named extension commands in autocomplete.
- `/login` lives in `modes/interactive/login-flow.ts`: provider options, auth-type and provider selectors, the Anthropic ToS gate, the custom endpoint wizard (an empty key is allowed and saved as `apiKey: "none"`), the credential dialogs and `completeProviderAuthentication`. Functions take a `LoginFlowHost` built by `InteractiveMode.createLoginFlowHost`. The same host pattern moved the loaded-resources listing (`loaded-resources.ts`), permission/plan/auto-review state (`PermissionModeController` in `permission-controller.ts`, owner of `previousPermissionMode`/`preGoalPermissionMode`) and model/subscription commands (`model-commands.ts`) out of `interactive-mode.ts`. `showSettingsSelector` stays: it touches 26 class members.
- `/plan <task>` enters read-only if needed and sends `Create a plan for: <task>`; `/plan off` restores the previous mode. `present_plan` stays available in read-only.
- `/chain` routing is in [subagents.md](subagents.md).

## /settings

- Sections are `SettingSection` rows in `SettingsList` (`packages/tui`). They are not selectable, search and the `(n/total)` counter skip them, and a filtered row keeps its section label. A section without a label only adds a blank row (used before Advanced). Top-level search matches Advanced rows through the Advanced row's `searchTerms` and shows the matching names as its value; the submenu shares the main change handler and item objects.
- Menu descriptions name the feature, not every control. Keep choice-specific limits beside the choice. Factory defaults apply to missing keys; explicit saved values win and no migration rewrites them.

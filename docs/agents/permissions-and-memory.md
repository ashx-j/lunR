# Permissions, auto review and memory

Read before changing permission modes, the auto reviewer, protected files, global instructions or memory.

## Modes

- `yolo | auto | ask | read-only` (`PERMISSION_MODES`, default yolo); Shift+Tab cycles that order and the TUI shows `read`. Fail-closed without a handler. Bash is a heuristic, not an OS sandbox.
- Read-only bash is fail-closed on anything bash rewrites before running: `$` expansions (also inside double quotes), `$'…'`, brace lists, a command word with a directory outside `/bin`, `/usr/bin`, `/usr/local/bin`, `/opt/homebrew/bin`, config-redirect env (`HOME`, `PATH`, `XDG_*`, `RIPGREP_CONFIG_PATH`, ...) and git `-C`/`--git-dir`/`--work-tree`/`--bare`. MCP direct tools whose name matches a trusted name (`READ_ONLY_TOOLS`, `REVIEW_FREE_TOOLS`, `browser`, `code_rewrite`, `subagent`) are skipped with a warning. For option-sensitive commands (sed, sort, file, find, rg, git) a word blocks when the literal text before its first unquoted glob is empty or only dashes (`*`, `-*`, `""*`, `\-*`). `yarn`, `file -C` and `less -k`/`--lesskey-*`/`-o` also block. `sed` walks its script with GNU grammar and blocks `w`/`W`/`e`, the `s` flags `w`/`e`, `-f`/`--file`, unknown or abbreviated long options and any script it can't parse; `r`/`R` stay allowed. `date` allows only display forms, since `-s` and a bare `MMDDhhmm` operand set the clock. `sort` blocks every prefix of `--output`, `--compress-program` (runs a program) and `--temporary-directory`, and `-o`/`-T` in a short cluster; `rg` blocks `--pre` and `--hostname-bin`; `hostname` blocks an operand, `-F`/`--file` and `-b`/`--boot`. Git rejects abbreviated diff options, so `--output` is matched exactly. A repository's own textconv or external diff driver still runs on `git diff`/`git log`, because read-only mode trusts the project's git config. `less +!cmd` is not a hole: the bash tool's stdout is a pipe, so less acts as cat.
- A `run_in_background` start is a plain `bash` call, so every gate sees it. `bash_job` is in `READ_ONLY_TOOLS`: it only reads or stops a job a gated call started.
- Read-only = `gateToolCall` + `readOnlyModeBlockReason` + `READ_ONLY_MODE_ADDENDUM`. It blocks unclassified extension tools, including direct MCP tools; the `mcp` proxy allows status, search, describe and ui-messages. Saved `manual`/`plan` values read as yolo/read-only without rewriting. Gateway switches to a saved writable mode pause in read-only until confirmed. Read-only does not revoke running full-access children.
- `READ_ONLY_TOOLS` may name only tools lunR registers, because any tool with a listed name skips the read-only gate. `permissions.test.ts` scans `src/` for tool names and fails on a stale entry. `lsp_rename` and `lsp_code_actions` stay on it: both return previews, and the LSP client handles no `workspace/applyEdit` or `executeCommand`.
- The only output redirects allowed are an unquoted literal `[n]>/dev/null`, `&>/dev/null` and `[n]>&m`; they are blanked before segment splitting so the `&` of `2>&1` isn't read as an operator. A segment `cd <dir>` with one literal argument is allowed, but after it `git`, `gh`, `npm`, `pnpm` and `bun` block, since `cd dir && git log` is `git -C dir log`. The bash tool starts every call in the session directory, so a lone `cd` can't move a later call. A first `cd .` or `cd <session directory as an absolute path without ..>` (`cd <project> && git status`, which models write by habit) counts as no change, when the caller passes `cwd` and not on Windows; `~/..`, `x/..` and other spellings Node resolves to the same place stay a change, because bash expands `~`, searches `CDPATH` and follows symlinks first: in the 27 benchmark sessions of 2026-11-26 that prefix caused 15 of auto mode's 78 reviewer requests.
- Read-only bash splits words and ends comments and brace lists only on bash's own breaks (space, tab, newline), never JS `\s`: bash reads `A=1<NBSP>ls touch x` as an assignment and runs `touch`. A here-document (`<<`, not the `<<<` here-string) blocks, because a quote in its body would hide the lines after the delimiter from the scan. Unquoted backslash-newline pairs are removed first, as bash does before tokenizing, except inside single quotes and comments, so `<\`+newline+`<EOF` is still `<<`.
- Read-only mode refuses a set subagent `sessionDir`, because children write their session files there.
- Auto = yolo plus the AgentSession review step (`core/auto-review.ts`).
- `load_tools` is in `READ_ONLY_TOOLS`: it only activates registered tools, and each loaded tool keeps its own read-only classification.
- In read-only mode a subagent's `output` must resolve inside the directory lunR made for that run (`<artifacts>/outputs/<runId>/` or the chain's `<chain-runs>/<runId>/`), and a set `chainDir` is refused. The launch sites check this with `readOnlyOutputError` (`pi-subagents/src/runs/shared/single-output.ts`), not the gate, so model and user `/chain` launches both hit it, `artifacts: false` refuses every output, and auto and ask mode treat the launch like master.
- "No questions" (`AUTONOMOUS_ADDENDUM`) is a per-session flag set by `/goal`, children and ACP Autonomous, not a mode.
- Ask = `gateAskMode` in `permissions.ts`: asks through the shared approval handler (`kind: "tool"`) before any call `readOnlyModeBlock` would block, so it has no classifier of its own and unknown tools ask. `REVIEW_FREE_TOOLS` (todo, goals) skip both ask and auto review. Session approvals exist only for bash (exact command) and `PATH_TOOLS` (exact path); other tools send `allowSession: false` (the removed manual mode keyed on the tool, so one "session" answer allowed every later call). No system prompt addendum: rejections return their reason. ACP maps ask to yolo because its client already approves each tool. `/goal` does not leave ask.
- Allow/deny rules (`core/permission-rules.ts`) come from `getPermissionRuleSettings()` per scope, never the merged settings. An untrusted project loads no settings, so `loadPermissionRules` reads its `permissions.deny` straight from the file (cron sessions are always untrusted). `compilePermissionRules` memoizes per cwd on the rule array identities; `addPermissionAllowRule` replaces the array so the memo misses. Deny runs before `READ_ONLY_TOOLS`, so it can block reads.
- Bash deny matching is `permission-rule-commands.ts`: one quote-aware pass that drops data (single quotes, double-quoted text outside substitutions, comments, redirect targets, here-document bodies unless they feed a shell), then emits a line at every wrapper stage. A here-document ends at its word after quote removal, as in bash (`<<\EOF` and `<<E"O"F` end at `EOF`); a word with `$`, a backtick, a line continuation or an unclosed quote makes the command `uncheckable`. `$(...)` and backticks use an explicit frame stack, `sh -c`/`eval`/`env -S`/shell here-document bodies go through a queue capped at `MAX_DEPTH`, and a segment cuts at most `MAX_STAGES` lines; each word and each segment's here-documents are queued at most once, so queued text stays within (MAX_DEPTH + 1) x the input. One work budget (`denyWorkBudget`, characters queued plus words visited, 4 per character per bash deny rule; the costliest realistic command measured 0.35) covers scanning and every rule's match. Past a cap or the budget the result is `uncheckable` and every bash deny rule matches, with its own refusal text. `denyLineMatch` reads per-segment word kinds and flag bitmasks (`factsOf`) and jumps over option runs when the pattern word can't match an option; identical rules compile once and a rule whose literal command word names no line skips them. A line is a view (`words`, `start`, `end`) on its segment, never a copy. `denyLineMatch` is one greedy forward pass per line, so a pattern word that equals an option's value is taken as the pattern word (`git -C push push` is missed). `globMatch`/`segmentsMatch` never backtrack; `MAX_RULES` and `MAX_RULE_LENGTH` cap each list and a dropped deny rule blocks its tool. It replaced read-only's `splitShellSegments`, which splits here-document bodies and comments into commands: read-only mode blocks `cat <<'EOF'` with any body for that reason. Each call resolves its path and real path at most once (`callView`, shared between `denied` and `allowed` by the args object).
- An untrusted project's deny rules come from `SettingsStorage.readWithoutLock`, a plain read that creates no lock folder in the repository. It is required on every storage, and an unreadable file records a settings warning. A trusted project reuses its normal load instead.
- Ask mode asks before a subagent launch whose `output` (own or inherited from `tasks`/`chain`/`parallel`) saves a file, even for read-only children, because lunR writes that file for the child. Read-only mode does not block it.

## Auto review

- Auto review runs in `AgentSession` after `gateToolCall`, not in `permissions.ts`, because it needs the model runtime, messages and session usage. Keep `needsAutoReview` derived from `readOnlyModeBlock` so new tools default to reviewed. It also reviews `web_fetch`/`fetch_content`, browser `navigate`/`tabs`, env-prefixed bash and hidden or outside paths (resolved with `resolveToCwd` + `canonicalizeTargetPath`).
- The reviewer never sees tool results. It clips long actions head-and-tail with a marker and lists `path`/`command`/`url` first. AGENTS.md and extension-sent user messages (tracked in a WeakSet by identity, lost after reload) are labelled as context that can't authorize anything. An aborted review returns early and never counts toward the ask-the-user limit. `autoReviewModel` is read from global settings only. The default reviewer is the newest model of the provider's `reviewerFamily` among the models the credential offers (a Claude subscription offers only its saved picker list), else the session model; never pin an exact reviewer id. A configured or parent reviewer the credential's model list doesn't include is `unavailable`, so the warning and picker fire; with no list (an env key, a subscription saved without models) any catalog model counts.
- `core/auto-review-skip.ts` (`AutoReviewSkips`, one per session) runs before `needsAutoReview`. A bash line skips the review request only when the module understands all of it; anything else, and any exception while deciding, goes to the reviewer as before. It has its own small lexer that refuses instead of parsing: literal words (unquoted `[A-Za-z0-9_./,:=+%@^-]`, single quotes, double quotes without `$` `` ` `` `\` `!`), parts joined by `&&`, `;` or newlines, redirects `>`, `>>`, `2>`/`2>>` (only to `/dev/null`), `2>&1`, `>&2`, `<`, and one `<<'MARKER'` here-document. No pipes, `&`, `||`, subshells, expansions or assignments.

  | Command | Options | Runs without review when |
  | --- | --- | --- |
  | `mkdir` | `-p -v --parents --verbose` | every path passes the path rule |
  | `touch` | `-a -c -m --no-create` | every path passes; an existing file is a single regular file |
  | `cp` | `-f -n -p -v` and long forms | every source is an existing regular file; the target is new or passes the change rule |
  | `mv` | `-f -n -v` and long forms | as `cp`, and every source passes the change rule |
  | `rm` | `-f -v` and long forms | every existing operand is a file that passes the change rule |
  | `sed -i` | `-i -E -r -n -e` | every script passes read-only mode's sed check and reads no file; every file passes the change rule |
  | `echo`, `printf`, `cat` | `echo -n -e -E`, `cat -nbsAETv`, none for `printf` | the only commands whose output may go to a project file; `cat` operands and `<` are existing regular files that pass the path rule |

  Path rule: relative (or under the session cwd by absolute name), no empty, `.`, `..` or hidden component after a leading `./`, and no existing component that is a symlink, checked with `lstat` from the cwd down, so the kernel can't resolve it elsewhere. Change rule (overwrite, append, `rm`, `mv` source, `sed -i` target): a single regular file (no FIFO, device or second hard link) that this session made and nobody changed (dev, inode, size and mtime recorded in `finished` from `afterToolCall`, only when the call succeeded), or that git proves unchanged. Later parts of a line are checked against what earlier parts did (`Plan.overlay`), so `mkdir -p a/b && touch a/b/c` skips and `mv work.txt n && echo x > n` is reviewed. The git proof is `git ls-files -s -v` (entry `H`, mode 100644/100755, stage 0, so not skip-worktree, assume-unchanged, a submodule or a nested repository) plus `git hash-object --no-filters` of the file; neither refreshes the index or runs a filter, and the child env drops every `GIT_*` variable.

  Always reviewed: lines over 4,096 characters or 64 paths, `run_in_background`, changes to existing files while a background job runs, `shellCommandPrefix` or `shellPath` set, a cwd of `/` or home, `BASH_ENV` or exported bash functions, and a relative or in-project `PATH` entry (lunR's own bin dir counts, so a profile inside the project turns the skip off). `write` and `edit` still follow `needsAutoReview`; the module only records the files they create. Plan cost: 36 µs for `mkdir -p a && touch a/x && echo hi > a/y` at load 5.3; the git proof is 2 parallel spawns, only for changes to files the session didn't make. A skipped action leaves no `auto-review` request in `/usage`, which is where a reviewed one shows. `git add`/`commit` stay reviewed because hooks and filters run project programs.
- ACP workers call `setAutoReviewEnabled(false)` and tie autonomy to ACP's `auto` (Autonomous), because the ACP client approves every tool itself. `-p` and gateway cron sessions in auto also set autonomy, preserving what a saved auto default meant before.

## Global instructions and memory

- Global behavior is optional `~/.lunr/agent/agents/AGENTS.md`: never auto-create it, add an in-app editor, or let model file tools modify it. A leftover `~/.lunr/agent/AGENTS.md` migrates there when the new path is empty. Per-model files are `~/.lunr/agent/agents/<model>/AGENTS.md` behind `/settings` Model instructions. Context breakdown labels it `Global AGENTS.md`. `behavior.md` is inert.
- `core/credential-files.ts` keeps the active profile's `auth.json`, `subscriptions.json` and `mcp-oauth/` out of tool calls. `gateToolCall` scans every call's string arguments (also inside arrays and objects, 3 levels deep) for the 3 names or the cached profile dir, then resolves only those strings, so no tool-name list is needed. It adds 0.2 to 0.4 µs per call when nothing matches; `getAgentDir()` alone costs 0.5 µs, which is why the fast test uses the dir cached by the last lookup. lunR's recursive tools share `credentialWalkFilter`, the read tool checks a renamed symlink with `credentialFileReason`, and bash resolves words after a literal `cd <dir>`. `test/credential-files.test.ts` runs every core and LSP tool's string parameters against the 3 locations, so a new tool fails it unless the gate covers it or `EXEMPT` names it with a reason.
- Memory (`~/.lunr/simple-memory/memory.md`) is durable facts only; the toggle removes injection/tools but keeps the file.
- `core/protected-targets.ts` blocks direct file-tool writes to global instructions, memory, settings.json, `auth.json`, `subscriptions.json`, `pr-watches/`, `install-features.json`, `gateway.json`, `pairing/`, `mcp-oauth/` and `claude-code/`. Login and the key pool write the credential files through `auth-storage.ts`, never the file tools. `models.json`, `mcp.json` and `web-search.json` stay writable on purpose, since users ask lunR to edit them. Bash is not covered: a shell command can still change a protected target. Read-only mode blocks only the shell writes its classifier recognizes, so it is not a guarantee either. The target and every policy root are canonicalized on every check, with one `lstat` per shared ancestor and no cache, because `git checkout` or another terminal can turn any component into a symlink. A subagent's `output` path is checked with `outputTargetError` (`pi-subagents/src/runs/shared/single-output.ts`) at every launch site, for every static chain step before the first starts, and again before the runtime writes the child's reply, because that write bypasses the file tools.

# Architecture

Read before adding features, extensions or bridges, or before syncing from upstream pi.

- **Features = baked-in extensions + bridges.** `builtin-extensions/` (factories registered in `builtin-extensions/index.ts`; hidden; vendored; 16 files still `// @ts-nocheck`: pi-subagents 10, pi-web-access 3, pi-mcp-adapter 2, pi-intercom 1; biome-excluded).
  - Light roster: simple-pi-memory, pi-tps, ashxj-tui, ashxj-spinners, ashxj-thinking, lunr-local-providers, lunr-todos, lunr-plan-tools, lunr-tool-loader, lunr-skill-creator.
  - Deferred (interactive after paint; print/RPC/gateway before first turn): pi-ollama-cloud, narumiruna-pi-goal, lunr-cron, lunr-pr-watch, pi-intercom, pi-prompt-template-model, pi-subagents, pi-web-access, lunr-browser, pi-lsp-extension, pi-mcp-adapter, lunr-computer-use.
  - Removed: lunr-settings-tools, lunr-behavior, context-mode, MattDevy + narumiruna collections. Extension absorption was rolled back; **never merge `archive/extension-absorption-DO-NOT-MERGE`.**
- **Bridges:** `globalThis[Symbol.for("@lunr/...")]`, read and written through `globalBridge<T>(symbol)` in `core/global-bridge.ts`. Never runtime-barrel-import `@earendil-works/pi-coding-agent` under `builtin-extensions/`, only concrete modules. `complete`/`streamSimple`/`getModel` come from `@earendil-works/pi-ai/compat`.
- **Cron:** `core/cron` in TUI (live session) and gateway (fresh headless session). One `jobs.json` in `~/.lunr/agent/cron/`. `runWithOrigin` ALS. Gateway fallback: `cronFallbackModels`. TUI cron uses the gateway's deliver allowlist. Schedulers without the lease retry it every tick; ownership counts only after `recoverInterruptedRuns` succeeds. A TUI owner skips, without claiming, jobs from other projects or with non-local targets (`SchedulerDeps.accepts`); missed one-shots go through `deliverFailure`. `cron resume` clears `interrupted` and the lease owner runs the job once. When the TUI owner skips due jobs it releases the lease for a gateway and waits `handoffBackoffTicks` (3) before retrying, so with no gateway its own jobs can run up to about 3 minutes late.
- **Gateway:** Telegram long-poll + Discord (mention-gated, no GuildMembers intent). Authz fail-closed. `ADAPTER_FACTORIES`. Details in [integrations.md](integrations.md).
- **ACP:** `lunr --mode acp` adapts pi-acp with one native RPC worker per ACP session. Setup, limits and T3 settings: `packages/coding-agent/docs/acp.md`.
- **Footer:** ashxj-tui `setFooter` only. Toggles are render-time `CustomizeBridge` reads.
- **Permissions:** see [permissions-and-memory.md](permissions-and-memory.md).
- **Rollback:** per-turn snapshots; `/rollback` forks and restores files. `/undo` rewinds the same session via `navigateTree` with no editor paste; `/edit` does that rewind then pastes. Neither forks.

## Renamed vs still "pi"

- Renamed: bin `lunr`, `.lunr/`, `APP_NAME`. **Never write `~/.pi/`.**
- Still pi: `@earendil-works/pi-*` scopes, `PI_CODING_AGENT*` env, `getPiUserAgent`, ExtensionAPI `pi`, package.json `"pi"`. pi-mcp-adapter still reads a legacy project `.pi/mcp.json` and treats `.pi` as a project-root marker on purpose.

## Code conventions

- `// lunr:` marks upstream edits. Hot sync files: `ashxj-tui.ts`, `interactive-mode.ts`, `agent-session.ts`, `bash.ts`, `settings-manager.ts`, `main.ts`, `builtin-extensions/*`.
- vite/oxc: `import type { A, B }`, not `import type { A, type B }`.
- New top-level CLI subcommands must be added to `DEFERRED_COMMANDS` in `startup/launch-routing.ts`; otherwise a TTY launch paints the chat TUI first and its editor also consumes the command's input.
- `--provider` only narrows `--model` lookup (`resolveCliModel`); it has no default and does nothing alone. Without `--model` the saved default model applies.
- Read `PI_OFFLINE` through `isOfflineModeEnabled()` (1/true/yes); a raw `!== undefined` check treated `0` as offline.
- `core/` loads without the TUI. Built-in tool drawing lives in `modes/interactive/tool-renderers/`, one file per tool, found by name through `getBuiltinToolRenderer`; core tool definitions have no `renderCall`/`renderResult`/`renderShell`, so `createXToolDefinition(...)` alone draws as a generic card. HTML export adds them back for built-ins with a lazy import in `exportToHtml`. `scripts/check-ts-relative-imports.mjs` fails a new `core/` import from `modes/`; its allowlist holds only the theme (shared with the extension API, and user themes link `theme-schema.json` by its path) and that export import.
- Create directories for model-supplied paths with `mkdirParents` / `mkdirParentsSync` (`utils/mkdir.ts`), not `mkdir({ recursive: true })`. Node's recursive mkdir loops forever at full CPU when a directory answers ENOENT although its parent exists (any new name under `/proc`), and nothing can stop it.
- Print and TUI signal handlers exit after `SIGNAL_DISPOSE_LIMIT_MS` (2 s) even when `dispose()` has not settled, because `dispose()` waits for the running tool and a tool that ignores its abort never returns.
- Process registry tracks direct children only; `nohup &` grandchildren are untracked.
- The bash tool stops a call after `bashTimeoutSeconds` (default 120) unless the call passes `timeout`. `getBashTimeoutSeconds` returns 0 for off and undefined for invalid values, so the description and the tool agree. Its commands get `GIT_EDITOR=true`, `GIT_TERMINAL_PROMPT=0`, `PAGER=cat` and `GIT_PAGER=cat` in `resolveSpawnContext`; user `!` commands go through `executeBash` with plain `getShellEnv()` and have no timeout. A call that starts `cmd &` and exits returns at once, and the timeout does not stop those children later; lunR lists their still-alive process groups on stderr at exit (`noteLeftoverProcesses` in `bash-jobs.ts`, one `kill(-pgid, 0)` per call, about 7 µs).
- Temp files: bash overflow logs (`lunr-bash-*.log`) are removed at process exit through `core/temp-files.ts` `removeOnExit`, never earlier, because the model is given their path. The Claude Code bridge removes its `lunr-claude-code-<pid>-*` process dirs at exit too. Interactive startup sweeps both kinds older than a day after first paint, and Claude Code dirs whose owner pid is gone. A print run killed by SIGINT (no handler there) or SIGKILL leaves them for that sweep.
- Every request stringifies system prompt plus tools for `getContextFingerprint` (`ai/src/utils/estimate.ts`), and V8's `JSON.stringify` gets about 100 µs slower once the result passes 65,536 chars, which the default tool set reaches. The last fingerprint is reused while the system prompt and each tool's object, `name`, `description` and `parameters` are the same, so reassigning one of those invalidates it, but a schema mutated deep in place does not.
- `run_in_background` jobs (`core/tools/bash-jobs.ts`) belong to `AgentSession.bashJobs`, shared with the `bash_job` tool through `createAllToolDefinitions`. `setActiveToolsByName` adds `bash_job` right after `bash` whenever bash is active. The shell writes straight to a log file under a `lunr-jobs-<pid>-*` temp dir, so lunR does no work per output chunk. Each job is its own process group: a job whose shell exited stays running (and stoppable) while `kill(-pgid, 0)` finds a member, so `cmd &` inside a job ends with the job. `_disposeSettled` stops jobs and removes the logs; an `exit` hook plus `signal-exit`'s `onExit` stop the rest and remove the dirs. Once a job's shell has exited its pid may be reused, so `killJob` signals only `-pgid`, and only while a member is alive; a 2 s unref'd timer drops jobs whose group emptied. `onExit` skips a signal another listener survives (the TUI's SIGINT guard while suspended), so those keep the jobs. After `kill -9` the job processes stay; the first job of the next lunR removes dirs whose pid is dead and that no write has touched for a day (a lunR in another pid namespace sharing `/tmp` looks dead). An exit the model has not read reaches it in the next tool result (`afterToolCall`) or as a `bash-job` custom message with the next prompt, never as a steer: a steer queued during a final answer makes the loop send one more request.
- Tree-sitter grammars: `scripts/copy-tree-sitter-grammars.mjs` is the one place that picks them. It takes `pi-lsp-extension/src/tree-sitter/vendored-grammars/` (newer TypeScript, TSX, JavaScript, Bash, C++ and Lua builds, hashes in its `manifest.json`, checked by `check:vendored-grammars`) and `tree-sitter-wasms` 0.1.13 for the rest; source runs pick per file the same way. The old builds have lexers V8 needs up to 2.2 GB to optimize, and its Swift build kills node with "Fatal process out of memory: Zone" seconds after the first Swift parse, so Swift has no grammar (Bun's JavaScriptCore would cope). V8 command-line flags such as `--liftoff-only` work only on the node command line; `--wasm-tiering-budget` is the one that also works through `v8.setFlagsFromString`, and `TreeSitterManager.init()` raises it 14x: the 500-call probe peaks at 330 MB instead of 830 to 970 MB and survives a 500 MB memory limit, where the default budget is killed at call 64. A grammar must stay ABI 14 until web-tree-sitter moves past 0.24.7. Pattern trees are parsed with `parseDetached` and freed; a parse past 5 s throws `ParseTimeoutError` and the tools name the skipped files.
- Lazy extension lifecycle: session replacement invalidates pending work before new work binds. Await extension `session_shutdown` before gateway/cron disposal. MCP closes partial connections and shares one shutdown promise; LSP serializes shutdown and bind; `subagent_wait` waits only for pending launch registration.
- Agent loop: an abort during tool preparation or execution turns unstarted calls into "Operation aborted" results and ends the run without another provider request; queued steering and follow-ups stay queued. A stream that ends without done/error becomes an error message.
- Parallel tool calls: `AgentSession` sets `toolCallMutates` from `readOnlyModeBlockReason`, so edit, write, mutating bash and the other calls read-only mode blocks wait for earlier calls and finish before later ones start. Read-only bash and read tools stay concurrent. Commands off the read-only allowlist (`ALLOWED_COMMANDS` in `core/plan-mode.ts`) count as mutating, so adding a command there also lets it run in read-only and ask mode without a question. Add only commands with no option that writes or runs a program. Unknown extension tools stay concurrent unless they set `executionMode: "sequential"`, which still serializes the whole message.
- User- and model-supplied regexes (MCP proxy search, the session selector's `re:` search) run in one shared eval `Worker` (`utils/regex-worker.ts`). The time limit (100 ms for MCP, 1 s for the selector) starts when the worker reports it started the job, so worker start-up never counts. A job that runs past it terminates the worker; the other jobs on it are retried once on a new one. A new worker starts only after the terminated one exits. Bun keeps running a terminated worker's regex for 1 to 5 s and its `Worker` API has no way to stop it sooner, so a search after a catastrophic one can wait that long under Bun. The selector sends its history to the worker once per session list, which blocks the main thread for about 100 ms in Node and 270 ms in Bun for 100 MB.
- `AuthStorage.reload` reads `auth.json` without the lock and keeps the last snapshot on an empty or unparsable file. Session files are created 0600 and directories lunR creates 0700. `navigateTree` (`/tree`, RPC) refuses while a run is active.
- Compaction caps `reserveTokens` at 25% and `keepRecentTokens` at 40% of the model window (`compactionSettingsForWindow`); `prepareCompaction` takes the window as its third argument. Below about 65k tokens the caps apply; larger windows keep 16384/20000.
- `compaction.ceilingTokens` lowers the trigger to `min(window - reserve, ceiling)` (`compactionThreshold`), with the ceiling raised to at least 2 × the compacted size (`compactionCeilingFloor`). The compacted size is the larger of prompt and tools + kept + reserve and `_compactedContextTokens`, the estimate of the rebuilt context recorded when a compaction succeeds (prefix plus `estimateMessagesTokens`, never provider usage, so a retried or zero-usage request can't change it; not persisted, so a resumed session starts from the estimate floor), which covers a kept tool batch larger than `keepRecentTokens`. The system prompt plus tool schemas measured 16k tokens in print mode and 18k in the TUI with a clean profile; MCP servers add to that and deferred tool loading cuts it, so the floor follows the measured prefix. A floor of only one compacted context left 16k to 23k tokens of room, so a 2-read prompt compacted every time. A set ceiling also turns on the between-tool-turn check in `_installAgentNextTurnRefresh` that only Codex had, and a failed or cancelled ceiling compaction (between tool turns or at a prompt's opening check) stops it until just before the next prompt's opening check; with no ceiling, compaction is identical to master. `flushCompactionQueue` steers queued messages into a run that is still streaming after a compaction ends, since a failed or cancelled one reports `willRetry: false`. `_compactionPrefixTokens` runs only with a ceiling and caches on the prompt string and tools array (1.4 ms per uncached count).
- `lunr doctor` counts a provider as ready when the runtime resolves auth for it, and reports saved logins, env keys, custom providers and local servers separately. It builds a cache-only runtime with `grokHome: null` so it cannot write auth.json.
- `packages/agent` no longer has the `harness`; `uuidv7` lives in `src/uuid.ts`.
- Extension aliases match prefixes. Keep the AI catalog directory ahead of its root compatibility-file alias.
- Usage records live in session custom entries outside model context. Request IDs survive receipt replay; forks carry context but no new spend. Unknown usage and prices stay distinct from measured zero.

## Agent-facing prompt and tools

- Tool schemas are the always-available discovery layer. Keep recovery/workflow instructions conditional in tool results where possible; reserve base-prompt rules for guidance required before the first call.
- `buildSystemPrompt` adds an `Environment:` block (working directory, git repository, OS, the date the session started) after the skills, in both the default and `customPrompt` branches. The permission addendum, memory and goal blocks come after it. On Anthropic the system prompt is one text block with one cache marker, so the block's position inside it does not matter there; a late position helps OpenAI-style prefix caching. The prompt is rebuilt only on a model switch, tool change, resource change or reload, so the date adds no cache misses inside a session, which is also why it is labelled as the session's start date. `examples/extensions/ssh.ts` and `gondolin` rewrite the block's directory lines.
- First-request fixtures hash the full default tool payload. Refresh both browser hashes after any agent-facing schema change (see [testing.md](testing.md)).
- Deferred tools: `DEFERRED_TOOL_GROUPS` in `lunr-tool-loader.ts` is the only list of tools that start unloaded; everything else stays loaded. A new builtin tool fails the deferred first-paint run until it is in that table or in the script's always-loaded list. The system prompt must not depend on whether a deferred tool is active (the cron line moved into the cron description for this), and `load_tools`'s description is built once per session, because either change rewrites the cached prefix at a load. A tool goes in the table only when the model reaches for it after deciding on that kind of work; tools an inbound message, goal state, plan mode or a fact worth remembering trigger stay loaded.
- Deferred tools decide at the first `before_agent_start`. A turn an extension starts with `sendCustomMessage({ triggerTurn: true })` (PR watch events, intercom, subagent steering) skips that hook, so when one is a session's first turn it sends the full tool list and the next user prompt then defers and rewrites the cached prefix once. Deciding earlier needs a hook that both paths emit before the run snapshots its tools; `agent_start` and `turn_start` fire after the snapshot.
- `LUNR_SYSTEM_INJECTION.md` is a local point-in-time effective-prompt snapshot, not an input. Regenerate it after changes to `system-prompt.ts`, active tools/extensions, `AGENTS.md`, skills, permission mode, goal state, memory, or `~/.lunr/agent/agents/AGENTS.md`.

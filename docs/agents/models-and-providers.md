# Models, catalog and providers

Read before changing the model catalog, model selection, login or provider transports.

## Catalog and selection

- Catalog: see `docs/agents/model-catalog.md`. Humans edit the generator/adapters and regenerate JSON; never hand-edit `catalog/providers/*.json`.
- Model facts come from models.dev, not code. A wrong fact goes in `packages/ai/src/catalog/rules.ts` with a `why`; never add id lists or id regexes to the generator. Provider endpoints and transports live in `packages/ai/scripts/catalog-providers.ts`.
- `npm --prefix packages/ai run generate-models -- --offline` regenerates from the last fetched sources, so two runs see identical inputs when comparing generator changes.
- Tests that exercise a transport build fixture models instead of `getModel("provider", "id")`: upstream sources drop models, and a pinned id breaks the build on the next regeneration. Catalog tests feed fixture models.dev rows to `modelsDevModels`.
- Multi-protocol providers pass their protocol union to `createProvider<...>` explicitly. Inferring it from the generated catalog broke compilation whenever upstream added or removed a protocol. `models.json` is one minified line on purpose; cache-only create prefers `official-catalog-cache.json`. There is no pi.dev catalog; `/refresh` is the only refresh command.
- Official rows without `compat`/`thinkingLevelMap` take a baked-in template in `refreshOfficialCatalog`: same id first, then the provider's first model. The first-model fallback gave Haiku 4.5 adaptive thinking, which Anthropic rejects.
- The shrink guard in `catalog-sources.ts` keeps a provider at its last-good copy when it loses more than 25% of at least ten models, and lets the rest of models.dev update. It used to reject the whole source, and one dropped provider (`iflowcn`, unused by lunR) froze every model from 2026-09-06 to 2026-10-25. A quarantined provider shows in `sources[].quarantined` of the published `catalog/publication.json` and stays frozen until someone checks the upstream change and deletes the `catalog-sources-v2-*` Actions caches.
- `ModelRuntime.getModel` prefers the available-snapshot row, which carries credential-specific limits from `filterModels`; the plain catalog row is the fallback.
- Logout and startup remove global `enabledModels` entries shaped `provider/...` whose registered provider fails `checkAuth` (`findSignedOutScopePatterns`). An env key still counts as a credential, so `/logout` of a stored key keeps the scope while the env key exists.
- `/model` lists stored credentials only (`auth.json`, subscriptions, `--api-key`); ambient env keys do not list models but still resolve for a selected model. Logout deletes that provider's `models-store` + user-models. `/refresh` calls `getAuth` before `GET /models` so expired OAuth refreshes; it rebinds the session model.

## Providers

- xAI shares the official `grok` OAuth client, rotates refresh tokens and revokes the family on reuse. Adopt `~/.grok/auth.json` only when lunR is expired or after `invalid_grant`; write RFC3339 `expires_at`; never overwrite a newer Grok family or treat `modify(undefined)` as adopt. Remap to re-login only on `invalid_grant`/revoked refresh (`/usage` also on 401 billing), never on timeout or 403. Token refresh caps at 30s.
- xAI effort maps and Responses transport live in `xai-effort.ts` (grok-4.6+ `xhigh`; grok-4.5+ Responses via `parseXaiGrok4Minor`). `withXaiEffortMetadata` also runs in `mergeCatalogLayers`. Completions exceptions go in `XAI_RESPONSES_EXCLUDED_MODEL_IDS`; Completions compat must not leak onto Responses.
- OpenAI GPT effort floors live in `openai-effort.ts` and fill only levels a catalog row leaves open, so models.dev levels win. Codex generation and live discovery share `packages/ai/src/catalog/codex.ts`. Discovery is client-version-gated: an old version can return 200 without new models.
- Codex uses each route's `context_window` as its compaction budget; `max_context_window` never becomes the default. Fast mode persists only for `openai-codex`.
- OpenCode free models follow `zen/v1/models` ∩ models.dev, not models.dev `deprecated` status. Keep `opencode` in `UNLISTED_PROVIDERS` (`live-catalog.ts`).
- Live discovery covers every built-in provider whose catalog transport has a list endpoint; `liveListProtocol` picks the request shape. A 400/404/405 from a list endpoint is a quiet `skipped`, because an `error` would show in `/refresh` and retry the whole refresh every minute instead of hourly. A 401/403 is an error that `refreshIfStale` does not retry early (`LIVE_LIST_REJECTED`). Anthropic and Google lists skip any login that is not a stored API key, since `getAuth` throws for old subscription and OAuth records.
- lunR has no Google OAuth: the pi baseline import already lacked `google-gemini-cli` and `google-antigravity`, and Google bans accounts used that way. A stored `google` record of type `oauth` is skipped in `resolveProviderAuth` and `checkProviderAuth`, so the env key still works; with no key, `getAuth` throws `GOOGLE_SIGN_IN_REMOVED`. The record stays on disk. Vertex ADC and service accounts are Google Cloud credentials, not this sign-in, and stay.
- Generic models.dev providers (`MODELS_DEV_PROVIDERS`) have no baked-in rows. Code that reads `bakedIn[0]` for a template or transport must fall back to the provider's definition. Keys lunR reads another way or that extensions register (`ollama-cloud`, `lmstudio`) stay out through `NOT_GENERIC` in `catalog/providers.ts`.
- `sync-model-catalog.mjs` leaves generic providers out of the checked-in `catalog/` (the CLI bundle) and keeps them in versioned publications, so their 5,000+ rows never enter the package or the startup cache.
- New listed ids resolve through `discoveredModel` in `packages/ai/src/catalog/providers.ts`, the function the generator uses for OpenCode's live-only ids. Change model resolution there, not in `live-catalog.ts`.

## Claude subscriptions

- `/login anthropic` downloads pinned Claude Code (`CLAUDE_CODE_VERSION` 2.1.310, in browser-safe `auth/anthropic-route.ts`; hashes in `utils/claude-code-release.ts`) into `~/.lunr/agent/claude-code/<version>/` after confirmation, verifies per-platform integrity and reuses Claude Code's own sign-in. The first answer a process gets from the pinned copy removes older `<version>/` folders there (`removeOldClaudeCodeVersions`, about 280 MB each). It keeps newer versions (a newer lunR on the same profile), folders with a live `claude.<pid>.*.download`, and everything while the saved command is another version or `claude-code/` is a symlink. A running lunR whose in-memory login names a removed version re-reads `auth.json` and spawns the version it names (`currentConnection` in the bridge). Setup reads only the picker (`initialize`) and saves a version 3 record `models: [{ id, route, contextWindow? }]` in picker order. It skips variants whose description mentions usage credits (no structured billing field). Version 1 and 2 records need `/login anthropic`.
- Since 2.1.310, `set_model` checks model access with Anthropic and `get_context_usage` sends `count_tokens`, so setup calls neither. A `[1m]` route records 1M; other routes omit `contextWindow` and `filterModels` keeps the catalog window. Records from 2.1.263 keep their measured windows. `/refresh` shows `claudeCodeUpdateNote` while the record's binary is older than the pin, because its model list came from that older picker.
- Version 3 records also keep each route's picker `description` ("Opus 5.5 · Best for ..."); older records lack it and need no new login. `filterModels` lists every offered id, catalog row or not. An id with no row borrows thinking, output limit and default window from the same-family row (`claude-<family>`) sharing the most leading id segments, newest on ties, and takes its name from the description. It borrows no price: its cost is 0 with `catalog.pricing: "unknown"`, like other unpriced models, because prices differ inside a family. A new family gets 128k, 8k and `reasoning: false`, so lunR sends no `thinking` and Claude Code keeps its own. `--model` reaches such a row through `modelRuntime.getModel` in `resolveCliModel`'s fallback, since `getModels()` is the catalog only.
- The saved picker list is what a subscription "offers": the `/model` picker and cycling use it. An exact Claude id outside it (`--model`, `/model <id>`, a saved default or a models.json entry picked by id) still goes to the bridge with the id as the route, because a login can predate a model the pinned Claude Code serves. A 404 for such an id, or a 403 whose message names it, becomes one line naming the model and `/login anthropic`. Claude Code's `result` keeps Anthropic's message (`API Error: 403 <message>`) but not the error type, so any other 403 (a disabled organization) passes through unchanged. `lunr doctor` lists catalog models newer than the login's newest in each family (`claudeModelsNewerThanLogin`), cache-only.
- The bridge sends lunR's history as `messages` in `CLAUDE_CODE_EXTRA_BODY`, which replaces Claude Code's own list, and queries with one `client_composed` user turn holding the first prompt text (the billing header's `cc_version` suffix hashes it). Each request is a new Claude Code process, so its turn-start context (date note, account email, auto memory) lands on the newest turn every time and moved the history cache marker. With the body route the prefix is byte-identical across requests; the bridge puts a 1h marker on the newest block, after Claude Code's two 1h system markers. Settings files over 2 MiB are refused, so a larger history falls back to stdin replay and loses history caching. The bridge then adds a `claude_code_history_replayed` diagnostic to the reply; the TUI warns when a session first crosses into it and `/context` shows it while the last reply has it. Check caching with `node scripts/check-claude-code-cache.mjs` (real requests).
- 2.1.310 adds its own `# Environment` note (working directory, platform) and model identity as `role: "system"` messages; only the stdin replay route sends them. `CLAUDE_CODE_SIMPLE` would drop them but also disables the subscription sign-in, so on that route the bridge spawns Claude Code in lunR's working directory to keep the note true. On the body route it spawns in an empty per-request directory, which skips Claude Code's per-start git commands and `rg --files` of the project. Empty `--setting-sources` keeps that directory's CLAUDE.md and settings out.
- Empty `--setting-sources` does not stop auto memory: without `CLAUDE_CODE_DISABLE_AUTO_MEMORY=1` Claude Code adds `~/.claude/projects/<repo>/memory/MEMORY.md` (a worktree maps to its main checkout) to every request. It also adds the signed-in account's email as a session-context reminder on the newest user message. 2.1.310 has no switch for that short of `ANTHROPIC_UNIX_SOCKET`, which changes the transport.
- Every request pays Claude Code's own startup, about 0.4 s to the first upstream byte on a quiet machine. `REQUEST_ENV` turns off the startup work that strace showed 2.1.310 honoring: git status, log and user name (`CLAUDE_CODE_DISABLE_GIT_INSTRUCTIONS`) and memory and CLAUDE.md loading (`CLAUDE_CODE_DISABLE_AUTO_MEMORY`, `CLAUDE_CODE_DISABLE_CLAUDE_MDS`). Skill, plugin, checkpoint and install-check switches showed no effect, and the only network calls besides the request are the `/api/hello` warm-up. Recheck these with strace on a pin bump.
- Subscription turns use an injected SDK `fetch`: Claude Code sends the request straight to Anthropic; lunR rebuilds SSE from `--include-partial-messages` `stream_event` lines, stops Claude Code at `message_stop`, and rebuilds HTTP errors from `api_error_status`. `terminal_reason: api_error` without status is a retryable network error. Local failures travel as SSE `error` because the SDK hides `fetch` exceptions. The loopback serves only the MCP tool inventory. On the replay route the bridge stamps the request model on every assistant frame or Claude Code drops signed thinking.
- Never set `ANTHROPIC_BASE_URL` for a real subscription turn, read Claude Code credentials, restore pi's Claude Code OAuth route, or fall back to direct OAuth HTTP. Setup discovery points Claude Code at a TCP tripwire that passes only the credential-free `HEAD /api/hello` warm-up (sent unless a proxy, socket or client cert is set). Bumping `CLAUDE_CODE_VERSION` needs all eight platform integrity values and a fresh live qualification, including a passing `scripts/check-claude-code-cache.mjs`.
- The AI package loads the Claude Code bridge through a computed import specifier; a literal path breaks the browser smoke check.
- Deferred tools on the bridge ride in `CLAUDE_CODE_EXTRA_BODY`: the bridge copies `defer_loading` onto the extra body's tools and prefixes each `tool_reference.tool_name` with `mcp__lunr__`. Claude Code passes the body's `messages` and `tools` through unchanged with tool search off, so no Claude Code switch is needed. Its transcript route is different: on the stdin replay it replaces every `tool_reference` with "[Tool references removed - tool search not enabled]". The replay therefore drops the references and sends the deferred tools the history loaded or called as normal tools; deferred tools it never used stay out of that request. Recheck on a `CLAUDE_CODE_VERSION` bump: a captured body must show `defer_loading` on the declared tools and the `tool_reference` unchanged.
- On the bridge the model calls an unloaded tool by the bare name `load_tools`' catalog shows (`cron`, not `mcp__lunr__cron`); the API returns that `tool_use` unchanged. The bridge accepts a bare lunR name so the agent loop can answer with its load hint instead of failing the turn.
- Offline test setup for the real binary is in [testing.md](testing.md).
